# WP4 联机玩法同步说明

## 实现范围

WP4 已实现一个可在 `WorldGenMap` 中直接验收的服务端权威玩法闭环：

此闭环由联机 `WP4` 面板与同步标记驱动，暂未把 SurvivalEngine 原有的采集、背包、建造、敌人及本地存档组件逐一改造成网络权威对象。进入联机房间时应使用 WP4 面板操作；旧单机组件不能视为已联网同步。

- 采集：服务器校验玩家真实位置、节点剩余量和操作冷却，再写入背包；资源耗尽后由服务器定时刷新。
- 背包：木材、石材、斧头和金币只保存在服务器会话状态中；每个客户端只能收到自己的背包明细。
- 制作：服务器按 `axe` 配方校验并扣除 2 木、1 石，防止重放请求重复制作。
- 建筑：服务器校验 `firepit`、`wall_wood` 的配方、材料、距离、坡度、物理碰撞、世界边界、建筑间距和总数上限，再扣除材料并生成全局建筑 ID。
- 敌人：服务器选择目标、移动、结算固定伤害、死亡和复活；客户端不能上报伤害或死亡结果。
- 共享委托：房间共同贡献 3 木、2 石，至少两名玩家参与；每名贡献者各可领取一次 10 金币。DeepSeek 只提供经过校验的展示文本，不可用时自动保留本地回退文本。
- 晚加入：房间处于 `InGame` 时允许新玩家加入，服务器只为该连接加载游戏场景，并发送包含玩家、资源、建筑、敌人和任务的完整快照。

当前房间仍是 WP3 定义的局域网直连会话，不包含互联网大厅、数据库持久化和断线重连恢复。服务器进程或 Host 结束后，本局权威状态随会话结束。

Windows Dedicated Server 构建入口会以 `FrameworkDemo` 为首场景并在服务安装完成后自动监听配置的 UDP 端口。若本机 Unity 未安装 Windows Dedicated Server Build Support，可使用 `Haven/Build/Windows Headless Server (module fallback)` 生成普通 Windows Player 子目标的无图形服务器，并以 `-batchmode -nographics` 运行；这适合本机功能验证，但不等同于正式 Dedicated Server 子目标产物。

## 防重复与安全规则

每个玩法请求都带有唯一请求 ID，服务器在本局中为每名玩家保存最多 65536 个 ID 且不淘汰旧 ID；同一请求重发不会再次获得物品、生成建筑、造成伤害或领取奖励。服务器同时应用以下规则：

| 操作 | 服务器规则 |
|---|---|
| 采集 | 3.25 米范围、0.35 秒冷却、节点必须有剩余量 |
| 制作 | `axe` 消耗 2 木、1 石；0.5 秒冷却 |
| 建造 | 5 米范围、0.5 秒冷却、材料充足、世界边界 30 米、坡度不超过 30°、无物理占用、建筑间距至少 1.5 米、全局最多 24 个 |
| 贡献 | 单次 1–10 件、0.2 秒冷却、不得超过委托剩余需求、至少两名玩家参与 |
| 攻击 | 3.5 米范围、0.4 秒冷却、敌人必须存活，每次固定 25 点伤害 |
| 领奖 | 0.5 秒冷却、共享委托完成、本人参与贡献且奖励未领取 |

客户端提交的建造位置只作为请求参数；玩家位置来自服务器拥有的 FishNet 玩家对象。客户端不提交背包数量、敌人生命、任务进度和奖励数量。

## 双机验收步骤

1. 启动 Dedicated Server 或房主，两个客户端使用相同协议版本加入同一房间。
2. 房主开始游戏；进入 `WorldGenMap` 后查看右侧 `WP4 服务端权威玩法` 面板。
3. 移动到棕色木材球或灰色石材球附近，分别采集木材和石材，确认只有采集者的私人背包增加。
4. 点击“制作斧头”，确认扣除 2 木、1 石并获得 1 `axe`。
5. 点击“火堆”或“木墙”，确认材料减少、建筑对所有客户端出现；在斜坡或已有物体处应被拒绝。
6. 两位玩家分批贡献 3 木和 2 石，确认共享进度一致；各自领取一次 10 金币，重复领奖被拒绝。
7. 靠近红色敌人连续攻击四次，确认双方看到一致生命值与死亡、复活状态。
8. 在游戏进行中启动第三个客户端并加入同一房间码，确认其看到此前的资源余量、建筑、敌人和共享委托，但看不到其他玩家的背包。
9. 让两个客户端同时采集最后一个资源或在同一点建造，确认服务器只接受满足剩余量/位置规则的请求。

## 自动化覆盖

EditMode 测试 `AuthoritativeGameplaySessionTests` 覆盖采集去重、距离校验、制作、建造扣料、共享贡献、重复领奖、私人背包、敌人复活和晚加入完整快照；`RoomSessionTests` 覆盖 InGame 晚加入及 Loading 阶段拒绝加入；`GlobalDataIdTests` 覆盖全部 SurvivalEngine CraftData 的全局 ID 唯一性。

由于新增了 AOT 服务契约和 FishNet 协议结构，正式构建前必须执行 `Haven/Framework/3. Generate All and Prepare DLL Assets`，并重新构建服务端与所有客户端。不同协议版本仍会在服务器执行玩法命令前被拒绝。

本机自动冒烟可启动服务器后，分别以 `-batchmode -nographics -haven-smoke-role=host` 与 `-batchmode -nographics -haven-smoke-role=guest -haven-smoke-room=<房间码>` 启动两份 Windows Offline Client。首个客户端日志会打印 `HAVEN_SMOKE_ROOM=<房间码>`；两份日志都打印 `HAVEN_SMOKE_PASS` 才算通过。探针验证房间加载、两人快照、权威采集、跨客户端节点余量同步，以及私人背包隔离。该探针不替代两台真实电脑上的 UI、网络与断线验收。

同一 Windows 用户同时运行两份客户端时，旧 SurvivalEngine 单机存档可能因共用 `player.survival` 输出文件占用警告。本机冒烟中的 WP4 联机操作仍通过；真实双机各自使用本地存档目录，但后续仍应将旧单机存档与联机流程彻底隔离。
