> 文档编号：PH-CLOSE-06  
> 版本：V1.0

> 编制日期：2026-09-22  
> 建议周期：10 个工作日，约 23.5 人日（客户端/UI、网络/服务端、测试/文档三条线并行）

## 1. 当前结论

项目已经具备 Unity 工程、单机地图与营地任务原型、FishNet 联机移动原型、DeepSeek 任务生成原型、HybridCLR + YooAsset 热更新基础以及网关测试基础，但距离“完成实训”还缺少完整的可演示闭环和正式交付材料。

收尾阶段不再扩展新玩法，目标是把现有原型整合成一条稳定流程：

`开始菜单 → 单人/联机 → 采集与建造 → AIGC 动态任务 → 双端同步 → 热更新验证 → Windows 可运行包 → 测试与文档证据`

### 1.1 完成判定

以下条件全部满足，才视为实训完成：

- Windows 主菜单可正常进入单人模式或联机模式，并可退出游戏。
- 两台电脑可创建/加入同一局，双方能看到彼此并完成一次共同采集和建造。
- 资源、背包、建筑、敌人和任务状态由服务端统一判定，重连或晚加入后状态一致。
- AIGC 任务能完成“请求、生成、校验、展示、进度、完成、奖励”的完整闭环；外部接口失败时有本地兜底任务。
- YooAsset + HybridCLR 能在第二台电脑完成一次版本检测、资源/热更代码下载和更新后启动。
- Windows 客户端、专用服务器、网关均有可复现的构建和启动方式，配置中不包含明文密钥。
- 自动测试、双机联调、异常测试和演示录像均留有日志、截图或视频证据。
- 任务书要求的报告、说明书、总结、答辩材料齐全，文档内容与最终程序一致。

## 3. 具体实施步骤

### WP0：冻结基线与建立验收清单（1.0 人日）

1. 备份并确认当前 `main` 分支可打开，记录 Unity 版本、包版本和当前提交号。
2. 保留现有未提交的 `Assets/DefaultPrefabObjects.asset` 与 `ProjectSettings/ProjectSettings.asset` 修改，先确认用途再提交，禁止直接覆盖。
3. 建立 `ReleaseCandidate` 验收清单，逐项对应本文件的 G01～G10。
4. 固定演示环境：Windows 版本、局域网地址、端口、网关地址、补丁服务器地址。
5. 每完成一个工作包，提交一次独立、可回退的 Git 变更，并附测试结果。

**验收标准：** 工程可在干净工作区打开；无编译错误；所有环境参数有记录；每个缺口都有负责人和状态。

### WP1：开始游戏菜单（1.5 人日）

#### 场景与资源

1. 新建 `Assets/Scenes/MainMenu.unity`，作为 Build Settings 的第一个场景。
2. 优先使用素材包中已有的 `Assets/Art/淘宝ui素材/RuntimeSprites`，从以下资源中挑选并统一风格：
   - 主背景：`Auth/UI_Auth_TitleStart_Background.png`
   - 标题/对比装饰：`Auth/UI_Auth_TitleStart_Contrast.png`
   - 按钮背景：`Auth/UI_Auth_TitleStart_ButtonStart_Bg_Background.png` 或 `Home/UI_Home_Menu_Btn_Normal*.png`
   - 中文字体：复用工程现有 TMP 中文字体资产。
3. Canvas 使用 `Scale With Screen Size`，参考分辨率设为 `1920 × 1080`，匹配宽高设为 `0.5`。
4. 所有按钮统一 Normal、Highlighted、Pressed、Disabled 状态，并提供点击音效。

#### 界面层级

1. `MainPanel`：游戏标题、“开始游戏”、“退出游戏”。
2. 点击“开始游戏”隐藏 `MainPanel`，显示 `ModePanel`：“单人模式”、“联机模式”、“返回”。
3. 点击“单人模式”显示短暂加载状态，然后进入 `WorldGenMap.unity`。
4. 点击“联机模式”隐藏 `ModePanel`，显示 `MultiplayerPanel`：“创建房间”、“加入房间”、“返回”。
5. “创建房间”启动 Host/Server，成功后进入 `FrameworkDemo.unity`；失败则停留并显示错误原因。
6. “加入房间”弹出地址/房间信息输入区，校验后发起连接；显示“连接中、连接成功、连接失败、超时”状态。
7. “退出游戏”在 Windows 包中执行退出；编辑器内只停止 Play，防止误报无效。
8. 所有子页面支持 Esc 返回上一级，连接中禁止重复点击。

#### 代码组织建议

- 在 `Assets/Hotfix/Runtime/UI/MainMenu/` 增加菜单控制、面板切换和连接状态代码。
- 场景加载统一走一个入口，禁止每个按钮自行硬编码重复逻辑。
- 联机按钮只负责收集参数和触发服务，不直接操作底层 Transport。

**验收标准：** 1920×1080 与 1366×768 下无拉伸、遮挡；所有按钮路径可达；单人进入 `WorldGenMap`；联机创建/加入均有明确结果；退出按钮在 Windows 包有效。

### WP2：单人模式最小完整闭环（1.5 人日）

1. 从主菜单进入 `WorldGenMap`，检查玩家出生点、相机、输入和 UI 初始化。
2. 固定一条 5～8 分钟演示路线：领取营地任务 → 采集指定资源 → 制作/获得建造材料 → 放置一个建筑 → 提交任务 → 获得奖励。
3. 给关键交互增加操作提示、任务目标、资源数量、失败原因和完成反馈。
4. 校验重复领取、资源不足、非法放置、任务未完成提交等边界情况。
5. 若已有存档系统则完成保存/读取验证；若没有，至少保证单局流程重进场景不会残留错误状态，并在用户手册中说明限制。
6. 清理演示路线中的缺失引用、红色控制台错误和明显穿模/卡死问题。

**验收标准：** 新玩家无需开发人员解释即可完成一次单人任务；整个流程无阻断、无 Error 日志，关键操作都有反馈。

### WP3：联机创建与加入房间（2.0 人日）

1. 统一网络配置：传输协议、监听端口、最大人数、连接超时和场景名。
2. 创建房间时由本机启动 Host；生成并展示可分享的局域网 IP/端口，房主进入等待/游戏状态。
3. 加入房间时校验 IP/端口格式，客户端连接成功后再切换场景或生成玩家。
4. 增加连接状态机：Idle、Starting、Connecting、Connected、Failed、Disconnected。
5. 阻止重复创建、重复加入、空地址加入以及连接过程中再次操作。
6. 处理房主退出、客户端主动退出、连接超时、版本不一致和服务器满员。
7. 本阶段可把“房间”定义为局域网直连会话，无需额外开发大厅列表；UI 和文档需明确这一点。

**验收标准：** 两台电脑在同一局域网内可稳定创建并加入；失败时 UI 有可理解的原因；退出后能返回菜单并再次连接。

### WP4：服务端权威的核心玩法同步（4.0 人日）

按以下顺序实现，完成一项就做双机验证：

1. **玩家状态：** 服务端生成玩家；位置/朝向同步；玩家离开时正确销毁。
2. **资源节点：** 客户端只发送采集请求，服务端校验距离、工具、冷却和剩余量，再广播结果。
3. **背包与材料：** 物品增减仅由服务端修改；客户端显示同步结果，不允许本地直接加物品。
4. **建筑放置：** 客户端提交预览位置，服务端校验材料、距离、碰撞和范围；扣除材料后生成网络建筑。
5. **敌人与伤害：** 敌人生成、目标、生命和死亡由服务端决定；客户端只提交合法攻击请求。
6. **任务状态：** 领取、进度、完成和奖励保存在服务端会话状态中，并同步给相关玩家。
7. **晚加入快照：** 新加入玩家能获得现有资源节点、建筑、敌人、公共任务等当前状态。
8. **防重复请求：** 为采集、建造、领奖增加冷却或请求标识，避免多次点击重复结算。

**验收标准：** 双端连续完成一次采集和共同建造；两端数量与建筑位置一致；晚加入能看到已有建筑；修改客户端本地数值不能获得有效资源。

### WP5：AIGC 动态任务联机闭环（2.5 人日）

1. 客户端只提交受限的任务请求参数，例如玩家等级、已有资源和区域；不直接访问 DeepSeek。
2. 服务端向网关请求任务；API Key 仅放在网关环境变量或本机安全配置中，不进入 Unity 包和仓库。
3. 固定响应 JSON Schema：任务 ID、标题、描述、目标类型、目标物、数量、奖励、超时/版本。
4. 网关和服务端都执行白名单校验：目标类型、物品 ID、数量范围、奖励上限、文本长度。
5. 响应非法、超时或限流时，从 `Assets/Hotfix/Content/CampQuestCatalog.json` 选择本地兜底任务。
6. 服务端创建任务实例并同步给玩家；采集/建造事件驱动任务进度，禁止客户端直接上报“已完成”。
7. 完成后由服务端发奖并记录一次性领取状态；两端 UI 同步刷新。
8. 保存去敏日志：请求 ID、耗时、使用 AI/兜底、校验失败原因，不记录密钥和完整隐私输入。

**验收标准：** 正常接口和断网兜底各成功完成一次任务；双端进度一致；非法 AI 输出不会进入游戏；奖励不能重复领取。

### WP6：HybridCLR + YooAsset 热更新验收（2.0 人日）

1. 确认热更程序集、AOT 补充元数据程序集和资源收集规则与当前版本一致。
2. 重新生成 HybridCLR 必要文件并构建最新热更 DLL，避免沿用过期的 `Assets/Hotfix/Generated/*.bytes`。
3. 构建首包 `v1.0.0`，上传对应清单、资源包和热更代码到补丁服务器。
4. 修改一个可见且低风险的热更内容，例如任务文本或菜单版本号，构建 `v1.0.1` 增量包。
5. 第一台电脑验证首包启动；第二台电脑从 `v1.0.0` 检查版本、下载 `v1.0.1`、加载并显示新内容。
6. 测试网络中断、清单不存在、文件校验失败、磁盘空间不足等失败提示，至少保证可重试或回到旧版本。
7. 保存版本号、文件列表、服务器日志、客户端日志和更新前后截图。

**验收标准：** 第二台电脑无需重新安装完整客户端即可获得更新；更新失败不会无限卡死；版本和证据可追溯。

### WP7：Windows 构建与部署（1.5 人日）

1. Build Settings 至少包含并排序：`MainMenu.unity`、`WorldGenMap.unity`、`FrameworkDemo.unity`。
2. 形成三类产物：Windows Client、Windows Dedicated Server、Gateway。
3. 将地址、端口、环境、补丁 URL 等抽离为配置，提供开发/演示两套示例配置。
4. 提供一键或明确顺序的启动方式：先网关 → 专用服务器/Host → 客户端。
5. 新机器按部署说明验证依赖、端口、防火墙和日志目录。
6. 发布包中移除源码密钥、临时缓存、无关大文件和个人路径。

**验收标准：** 在非开发机上按说明可启动全部组件；客户端能进入单人和联机；日志可定位连接及热更新问题。

### WP8：测试、联调与缺陷关闭（3.0 人日）

1. 重新执行 Gateway 自动测试，保存最终通过数量和日志；已有 45/45 只能作为历史基线，最终包需重新跑。
2. 执行 Unity EditMode/PlayMode 测试，补充菜单状态切换、任务规则、输入校验和重复领奖测试。
3. 完成双机局域网测试：创建、加入、采集、建造、AIGC 任务、掉线、退出、再次加入。
4. 完成热更新测试：无更新、有更新、下载失败、校验失败、重试成功。
5. 完成 UI 测试：1920×1080、1366×768，中文无缺字，按钮无越界。
6. 完成至少 30 分钟稳定性运行，观察内存、重复生成、断线和控制台错误。
7. 缺陷按“阻断/严重/一般/建议”分级；阻断和严重缺陷必须关闭，一般缺陷需写明是否延期。
8. 为每个验收点保存用例、结果、截图/日志路径和版本号。

**验收标准：** 最终测试报告中无未关闭阻断/严重缺陷；核心演示流程连续执行两次成功。

### WP9：正式文档补全（4.0 人日）

1. 根据最终实现更新现有 `doc/00`～`doc/05` 文档，删除模板占位内容，统一版本号、术语、端口和架构图。
2. 完成《测试报告》：环境、用例、结果、缺陷、回归、截图和结论。
3. 完成《部署说明》：客户端、服务器、网关、热更新服务的构建、配置、启动、停止和排错。
4. 完成《用户操作手册》：菜单、单人、创建房间、加入房间、任务、采集、建造、退出。
5. 完成《维护手册》：目录结构、模块依赖、配置项、日志、版本发布、热更新和常见故障。
6. 完成《项目总结报告》：目标、完成情况、技术路线、创新点、测试结果、问题与改进。
7. 所有文档引用最终截图和实际数据，不填写未经验证的通过率、性能值或功能结论。

**验收标准：** 文档与最终包一致；无空白占位符；新成员仅依靠文档即可部署并完成演示流程。

### WP10：答辩与最终交付（1.5 人日）

1. 制作答辩 PPT：背景与目标、总体架构、核心玩法、联机同步、AIGC、热更新、测试结果、总结。
2. 编写 6～8 分钟演示脚本，严格使用已经验证的固定路线。
3. 录制兜底视频：主菜单 → 双机联机 → 共同采集/建造 → AI 任务 → 热更新前后对比。
4. 整理证据目录：构建版本、测试日志、截图、视频、关键配置和文档。
5. 在演示设备上完整彩排两次，并准备断网时的本地任务兜底和视频兜底。
6. 按任务书清点并压缩最终交付包，确认可解压、可启动、无密钥。

**验收标准：** 演示脚本在规定时间内连续成功两次；PPT、视频、代码、运行包和文档均在交付清单中可打开。

## 8. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 新增 UI 素材导入设置不正确 | 图片模糊、九宫格拉伸或包体增大 | 统一 Sprite 类型、Pixels Per Unit、压缩和 9-slice 边框后再搭界面 |
| 联机功能范围继续扩大 | 核心闭环延期 | 房间先限定为局域网直连，不做账号、匹配和云大厅 |
| 客户端拥有业务判定权 | 作弊、不同步、重复奖励 | 采集、建造、任务和奖励全部由服务端校验 |
| DeepSeek 不稳定或无网络 | 演示中断 | 严格超时并使用本地任务目录兜底 |
| 热更新文件与客户端版本不匹配 | 启动失败 | 版本化清单、哈希校验、失败回退、保留旧版本 |
| 文档提前编造结果 | 答辩时内容与程序不一致 | 测试完成后再填写数据，只引用真实截图和日志 |
| 时间不足 | 功能与材料都不完整 | 先完成 P0 闭环，暂停美术润色和非必要玩法 |
