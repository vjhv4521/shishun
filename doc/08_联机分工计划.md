# 0.2.0 联机玩法完整分工计划

## 目标

在不影响既有单机玩法的前提下，完成可由 Dedicated Server 或 Host 权威运行的双人合作闭环，并交付 Windows `0.2.0` 客户端、服务端和可复现的验收记录。所有变更完成后保留在工作区供检查，不自动 commit 或 push。

## 工作包

1. **恢复计划与边界**：维护本文件；WP4 使用一套 `ICoopGameplayService` 契约，不并行保留重复玩法服务。
2. **数据 ID 治理**：修复植物与物品共用 `grass` ID；新增覆盖全部 SurvivalEngine `CraftData` 的全局唯一性测试。
3. **版本升级**：FishNet 协议升至 `3`，Unity App Version 与热更新 App Version 升至 `0.2.0`；旧客户端必须在认证阶段被拒绝。
4. **稳定契约**：提供合作玩法服务、私人背包、命令结果、共享任务快照，以及状态、背包、任务和命令完成事件。
5. **私人背包与幂等**：背包只由服务器写入，客户端快照只包含自己的明细；每名玩家保存有限请求历史，重复请求不得重复产生效果。
6. **权威采集**：实现木材、石料节点的服务端距离、冷却、剩余量和恢复计时；竞争最后一份资源时只允许一次成功结算。
7. **权威制作**：实现 `axe` 配方、材料扣除、冷却和重复请求保护。
8. **权威建造**：实现 `firepit`、`wall_wood`，由服务器校验材料、玩家距离、地面坡度、物理碰撞、建筑间距和房间数量上限。
9. **共享委托**：实现房间级委托、玩家分批贡献、每名成员一次性领奖；DeepSeek 仅生成安全范围内的展示文本，失败或内容无效时使用本地固定回退。
10. **FishNet Prefab 与单机隔离**：验证 `HavenPlayer` 已注册进 `DefaultPrefabObjects`；合作服务只由联机场景安装，原 `WorldGenMap` 单机入口不依赖 FishNet 会话。
11. **自动化验证**：执行并修复 Unity EditMode、PlayMode、项目校验和 Gateway 测试。
12. **正式构建**：执行 HybridCLR Generate All，构建 `0.2.0` Windows Offline Client 与 Windows Dedicated Server。
13. **冒烟与双机验收**：本机服务器＋双客户端自动冒烟覆盖创建、加入、入场、权威采集同步和私人背包隔离；制作、贡献、建造、领奖、晚加入、退出的规则由自动化单元测试覆盖，并在真实双机网络验收中按说明逐项手测。
14. **交付方式**：不自动 commit 或 push；报告构建位置、日志、测试结果、已知限制和双机待办。

## 验收重点

- 两个客户端不能通过伪造数量、伤害、位置或重复请求复制资源和奖励。
- 晚加入者看到当前节点、建筑、共享委托和公开玩家状态，但看不到其他玩家的私人背包。
- 同一玩家只能领取一次共享奖励；不同玩家都能各领取一次。
- DeepSeek 或 Gateway 不可用时不阻塞玩法，任务使用本地回退文本。
- 单机从主菜单进入 `WorldGenMap` 时，原角色、营地管家、背包和任务链保持可用。
